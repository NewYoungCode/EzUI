# EzUI htm/style 方言说明

## 先说结论

EzUI 的 `.htm` 不是 HTML。  
EzUI 的 `<style>` 不是标准 CSS。

它们只是“长得像”，不能按浏览器心智直接推断行为。

## 应该怎么理解

| Web 概念 | EzUI 中更接近的真实含义 |
| --- | --- |
| HTML 页面 | 控件树声明文件 |
| DOM 节点 | `Control` 实例 |
| iframe | `Frame` 控件 / 隔离子树 |
| CSS | 框架内部解析的样式子集 |
| 浏览器布局流 | `VLayout` / `HLayout` / `Spacer` / 固定尺寸组合 |
| jQuery 选择器 | `UISelector`（链式控件查找） |
| 右键菜单 | `PopupMenu` / `SystemMenu` |
| tooltip | `ToolTip` 控件 |
| 系统托盘 | `TrayIcon` |

## 不要默认成立的事情

- 不要默认标准盒模型行为。
- 不要默认所有控件都像网页输入框一样处理 `padding`。
- 不要把 `margin`、`padding`、`border`、`background-color` 这类样式直接写成节点属性；节点级覆盖统一写进 `style`。
- 不要默认“出现过一次的 CSS 值”在所有控件里都稳定。
- 不要默认深色 PNG 图标在深色背景上可见。
- 不要默认内容超界时会自然滚动或自动扩展父容器。
- 不要默认文本块一定会自动占据正确高度。
- 不要忘记 `vbox` 子控件默认就会横向吃满、`hbox` 子控件默认就会纵向吃满；很多情况下不需要再补 `width="100%"` 或 `height="100%"`。
- 在这个框架里，如果根控件显式指定了宽高，载入该界面的窗口宽高会跟根控件一致。也就是说，根控件写了多大，窗口本身就多大；不是“窗口里面再放一个这么大的内容区”。
- 不要把所有容器里的 `100%` 都按同一套心智理解；`vbox` / `hbox` 是布局器，`vlist` / `hlist` 是列表控件，它们的尺寸语义要分开判断。
- 不要把 `width="100%"` 和左右 `margin`、或 `height="100%"` 和上下 `margin` 直接叠在一起；这种组合很容易让控件显示出界。水平和垂直同理。
- 不要再写 `margin: 0 28 0 28` 这类省略单位的长度值；按当前规则，`margin`、`padding` 等长度都显式写 `px` 更稳妥。
- 不要默认给 autosize 的 `Label` 写了 `align` 就一定能看到效果；如果在某个方向上没有多出来的空间可供对齐，不管是水平还是垂直，`align` 都可能只是写了但不会产生可见变化。
- 不要把 `hbox` / `vbox` 的 `items-align` 直接按 Web 的 `align-items` 去理解；它更接近 Qt 布局里的对齐语义，支持单值或双值，像 `items-align="top left"` 这样可同时表达垂直和水平方向。
- 不要把 `iframe` 理解成 window 层对象；在 EzUI 里它映射到 `Frame` 控件，本质上仍在控件树里，只是带作用域隔离。
- 不要在已经 `100%` 跟随列表容器的 item 上，再用同方向的 `margin` 去做人为缩进；这类留白更适合写到列表控件自己的 `padding`，否则滚动条更容易压住子控件。
- 在这份技能里，只按 `event="none"` 理解鼠标忽略规则即可：它表示这个控件忽略鼠标事件。

## 更稳妥的写法策略

### 1. 优先复用正例

先从这些来源找正例：

- EzUI 框架 `README.md`
- 当前项目中同类 `.htm` 页面
- EzUI 官方示例中的同类实现
- `EzUI/UIStyle.h` 头文件

### 2. 先用保守语法把页面做稳

优先级从高到低：

1. 固定色
2. 固定圆角
3. 固定边框
4. 已存在的背景图片
5. 已有项目中出现过的 hover 状态

在页面稳定前，不要先追求复杂视觉效果。

### 3. 固定尺寸窗体先做预算

对于登录窗、弹窗、工具窗：

- 统计 `spacer`
- 统计写在 `style` 里的 `margin-top`
- 统计固定高度控件
- 给独立文本 `Label` 先判断是否更适合 `auto`，尤其是大字号文本优先给 `height="auto"`；如果需求是单行截断，则保留稳定单行高度并使用 `ellipsis="..."`，不要和自动撑高混用
- 发现超界就立刻修，不要指望框架自己兜底

### 4. 深色主题先检查图标

只要用了深背景，就必须检查：

- 设置图标
- 关闭图标
- 搜索图标
- 菜单图标
- 输入框前缀图标

如果图标看不清，优先做这些修正：

1. 换浅色资源
2. 给图标加浅色底板
3. 改成文字按钮
4. 改成自绘

## 已确认可用的颜色语法

以下颜色格式在 `UIStyle.h` 和项目示例中有明确使用（代码推断）：

| 格式 | 示例 | 说明 |
| --- | --- | --- |
| 十六进制 6 位 | `#FF5500` | RGB |
| 十六进制 8 位 | `#FF5500FF` | RGBA（含 alpha） |
| `rgb()` 函数 | `rgb(255,85,0)` | RGB 函数写法 |
| `rgba()` 函数 | `rgba(255,85,0,0.5)` | RGBA 含透明度 |
| 命名颜色 | `red` `blue` `black` `white` `green` `yellow` `orange` `purple` `gray` `transparent` | 内建颜色名 |

### 谨慎使用

- `rgba()` 在项目样例中出现过，但不要推断所有控件、所有场景下都稳定。
- 命名颜色列表以头文件中实际解析的为准，不要假设支持浏览器全部 140+ 命名颜色。
- 十六进制颜色是最安全的写法，优先使用。

## 已确认可用的渐变语法

从 `EzUI/Gradient.h` 和 `UIStyle.h`（代码推断）：

- 框架支持线性渐变（`LinearGradient`）、径向渐变（`RadialGradient`）、锥形渐变（`ConicGradient`）。
- 渐变扩展模式支持 `Pad`（默认）、`Reflect`、`Repeat`。
- 渐变主要通过 C++ API（`Graphics` 绑定）使用，在 `<style>` 中是否有 CSS-like 简写语法未明确确认。
- 如需渐变效果，建议优先在 `OnPaint` 自绘中使用 `GradientBrush`，而不是在样式块中猜测语法。

## 动画也要按方言思路做

- 入场动画优先改 `Opacity` 和 `Location`
- 切页动画优先用 `TabLayout::SlideToPage(...)`
- 不要先用会引发布局变化的宽高动画
- 任何动画都要检查会不会造成裁切和重叠

## 最后的验证标准

如果改完页面后出现下面任一现象，就说明你把它当成网页写了：

- 文本叠在一起
- 底部被裁掉
- 图标像消失了一样
- 宽高刚好“差一点点”
- 动画一做布局就乱

这时不要继续堆样式。先回到更保守的 EzUI 正例写法。
