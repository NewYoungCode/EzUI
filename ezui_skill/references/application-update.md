# EzUI 应用更新流程

本文件不是 EzUI 框架的启动要求。只有软件明确需要自更新、修复或文件替换能力时才读取并采用。

## 推荐职责

使用 `Launcher -> Updater -> App` 三段式：

- `Launcher`：唯一稳定入口，只负责版本检查和启动决策。
- `Updater`：只负责等待旧进程退出、备份、替换、清理和拉起新版本。
- `App`：只负责业务功能，不承担替换自身文件的职责。

## 标准闭环

1. `Launcher` 读取本地版本并请求服务器最新版本。
2. 没有更新时，直接启动 `App`，随后退出 `Launcher`。
3. 有更新时，`Launcher` 把最新 `Updater` 下载到临时目录，启动它后立即退出。
4. `Updater` 等待旧 `App` 退出；确有必要时再结束旧进程。
5. `Updater` 先备份旧版本文件，再把新文件覆盖到安装目录。
6. 替换成功后清理临时文件，启动新 `App`，最后退出 `Updater`。

## 边界

- 不把业务逻辑放入 `Launcher`。
- 不让 `App` 自己覆盖正在使用的程序文件。
- 更新流程必须有失败处理和可恢复路径；备份成功前不要破坏当前可运行版本。
- EzUI 只负责该工具链的界面时，仍遵守公开 API、UI 线程和资源管理规则。
